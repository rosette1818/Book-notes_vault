# Book & Notes Vault
## M1 — Specification, Data Model, Wireframes & Accessibility Plan

### 1. Project Overview

**Project name:** Book & Notes Vault

**Theme:** Book & Notes Vault

**Purpose:**  
Book & Notes Vault is a personal digital catalog for organizing and managing information about books. Users can add, view, edit, delete, search, and sort book records. The application will also provide statistics about the collection and allow data to be stored locally and transferred using JSON.

**Technology:**  
- HTML
- CSS
- Vanilla JavaScript
- Browser localStorage
- JSON

The application will be designed as a responsive, accessible single-page application.

---

## 2. Design Direction

### Visual Style

The chosen visual direction is **Academic / Library**.

The design will aim to be:

- Clean
- Organized
- Spacious
- Easy to read
- Professional
- Inspired by books and libraries

The interface will use clear headings, readable typography, consistent spacing, simple controls, and visually distinct sections.

### Responsive Strategy

The application will use a mobile-first approach.

Target layouts:

- Approximately 360px: mobile
- Approximately 768px: tablet
- Approximately 1024px and above: desktop

On larger screens, book records will be displayed in a table. On smaller screens, the records will become individual cards so that the information remains easy to read and interact with.

---

## 3. Application Sections

### Dashboard

The Dashboard will provide an overview of the user's book collection.

It will contain:

- Total number of books
- Total number of pages
- Most common/top tag
- Last-seven-days activity/trend

### Books

The Books section will display all stored book records.

It will provide:

- Search
- Regular-expression search
- Case-insensitive search option
- Sorting
- Edit controls
- Delete controls

Desktop will use a table layout, while mobile will use cards.

### Add/Edit Book

The form will allow users to create new book records and edit existing records.

Required fields:

- Title
- Author
- Pages
- Tag
- Date Added

Validation messages will be displayed when entered information is invalid.

### Settings

Settings will provide controls related to application preferences and data.

Planned features include:

- JSON export
- JSON import
- Search/display preferences
- Information about local browser storage

### About

The About section will explain the purpose of the application and provide:

- Project purpose
- GitHub repository link
- Contact email

## 4. Data Model

Each book record will contain the following fields:

| Field | Purpose |
|---|---|
| `id` | Unique identifier for the book |
| `title` | Book title |
| `author` | Author name |
| `pages` | Number of pages |
| `tag` | Category/tag for the book |
| `dateAdded` | Date the book was added |
| `createdAt` | Timestamp when the record was created |
| `updatedAt` | Timestamp when the record was last updated |

### Example Record

```text
ID: unique identifier
Title: Atomic Habits
Author: James Clear
Pages: 320
Tag: Self-Development
Date Added: 2026-10-07
Created At: creation timestamp
Updated At: update timestamp
```

The `id`, `createdAt`, and `updatedAt` values will be managed by the application rather than entered manually by the user.

## 7. Accessibility Plan

Accessibility will be considered throughout the application rather than added only at the end.

### Semantic Structure

The application will use appropriate semantic landmarks, including:

- `header`
- `nav`
- `main`
- `section`
- `footer`

### Keyboard Navigation

All interactive elements must be usable with a keyboard.

The planned keyboard flow is:

**Skip link → Navigation → Main content → Search → Records → Actions → Forms → Settings**

Users should be able to reach and operate controls using keyboard navigation without requiring a mouse.

### Skip Link

A visible-on-focus "Skip to main content" link will allow keyboard users to bypass repeated navigation.

### Form Accessibility

Every form control will have:

- A visible label
- A clear purpose
- An associated validation/error message where necessary

### Focus

Interactive elements will have a visible focus state so keyboard users can identify where they are on the page.

### Status and Live Messages

The application will provide accessible status messages for important actions, such as:

- Book added successfully
- Book updated successfully
- Book deleted
- Search results updated
- Import completed
- Export completed
- Validation errors

### Search Accessibility

Search matches will be visually highlighted while preserving understandable content for assistive technology.

### Responsive Accessibility

The interface will remain usable at mobile, tablet, and desktop widths. Controls will remain readable and sufficiently easy to interact with at smaller screen sizes.

---

## 8. Planned Validation

The application will use regular expressions as part of its validation and search functionality.

Planned validation areas include:

- Title/description whitespace
- Numeric page values
- `YYYY-MM-DD` date format
- Tag characters
- Detection of repeated words using a regex backreference

The application will also support regular-expression searching and handle invalid regular expressions safely.
